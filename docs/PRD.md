## 1. 产品目标

运营发现配送投诉变多，希望先确认送达时效是否变差，再决定先排查哪个地区或物流阶段。系统接收中文问题，返回可复算的统计结果、查询轨迹和需要补充的证据，让运营可以从结论直接进入下一步调查。

首版交付一个可本地演示的运营工作台。**简单问题查一次即可回答。调查问题允许模型读完查询结果后选择下一步。** 项目验收同时检查数字是否正确、调查路径是否有效，以及查询是否在授权范围内。

## 2. 用户与权限

| 角色 | 数据范围 | 典型任务 |
| --- | --- | --- |
| 总部运营 | 全部已导入的州 | 对比两个月的整体表现，找出新增超期订单集中地区 |
| 州运营 | 授权州及其下辖城市，首版演示州为圣保罗州（`SP`） | 查本州时效、定位优先排查的城市 |
| 项目演示者 | 使用上述两个演示账号 | 复现数据、展示调查流程与权限差异 |

用户未指定地区时使用其授权范围，并在答案标明实际查询范围。用户明确要求超出权限的地区时，系统反馈可查范围。州运营提出“全国超期率是多少”时，需要明确提示权限受限。

## 3. MVP 范围

### 首版功能

- 从 Olist 下载并导入订单、客户两张 CSV，形成一行一个订单的分析表。提供独立的合成数据演示。
- 支持单月查询、两月对比、按收货州拆分、在指定州内按城市拆分，以及查询单月或比较两个月的两个物流阶段耗时。
- 支持中文提问、每轮集中澄清所需的缺项、会话内追问，以及从州结果点击进入城市查询。
- 支持总部和州账号。每条答复展示有效范围、数据依据和实际查询步骤。
- 同一数据与指标口径下，比较规则调查与模型调查，给出正确率、边界表现与查询成本。

自动异常调查首版围绕超期率和配送阶段展开。已送达单数和平均送达耗时可单独查询或对比，也可作为调查的辅助证据。

### 后续扩展范围

实时订单接入、承运商和仓库维度、全链路物流轨迹、日报订阅、自动派单、多数据源以后的统一指标管理，均在首版验收后按需要评估。

## 4. 业务口径

所有月份按**下单时间**归组。7 月 31 日下单、8 月签收的订单归到 7 月。时间区间从当月第一天起，到下一月第一天之前。地区使用**客户收货州和城市**。

| 指标 | 定义 | 结果展示 |
| --- | --- | --- |
| `delivered_count` 已送达订单数 | `order_status = delivered` 的订单数 | 单数 |
| `late_rate` 送达超期率 | 已送达且预计、实际送达日期齐全的订单进入分母。实际送达日期晚于预计日期的订单进入分子。当天送达算准时。 | 超期单数 / 有效样本数、百分比。两月差值用百分点。 |
| `avg_delivery_days` 平均送达耗时 | 已送达且下单、签收时间齐全且顺序有效的订单，从下单到签收的平均耗时 | 天数、有效样本数 |
| 配送阶段耗时 | 从超期率有效样本中，选取下单、交接、签收时间依次不减的订单。对同一批订单分别算下单到交接、交接到签收。 | 每阶段中位数、P90、有效样本数和剔除数量。中位数与 P90 均用连续分位数。 |

有效样本存在、超期单数为零时显示 **0%**。分母为零时显示**无可计算数据**。查询同时保留超期单数增量和超期率变化，回答“新增超期单最多”或“超期率上升最多”时使用对应排序。定量结论同时给出统计月份和范围。

### 证据能支持到哪一步

订单与客户数据可以支持整体、州和城市的时效对比。交接时间可以帮助判断哪个阶段值得继续调查。要判断具体承运商、仓库或物流节点的责任，需要补充相应的明细或轨迹。系统可以明确输出需要补充哪些数据。 [Olist 原始数据](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)

## 5. 功能需求

| 编号 | 功能 | 用户可观察的行为 |
| --- | --- | --- |
| FR-01 | 数据导入与来源 | 可导入两个原始 CSV，也可使用合成数据启动。页面明确显示数据名称、覆盖月份和当前样本。 |
| FR-02 | 指标查询与比较 | 明确的单月或两月问题执行一次统计查询，可显示两期数字、分子分母、差额及有效样本。 |
| FR-03 | 澄清与追问 | 优先使用用户当前明确说出的条件，其次沿用同一会话中的已确认条件，再使用页面上可见的默认值。时间与指标已知且用户问目标月是否变差时，可默认和上一月比。仍缺必要条件时，本轮合并询问并暂缓统计。继承或默认的条件在答案中标明。 |
| FR-04 | 多步异常调查 | 从已核实的结果决定是否进一步按州、按城市或按阶段查。用户明确指定了地区或阶段时直接按该范围处理。 |
| FR-05 | 前端与可核验证据 | 提问区、比较区与证据区展示结论、指标口径、查询范围、实际查询轨迹。州结果支持点击下钻。 |
| FR-06 | 账号与行级权限 | 账号决定可见范围。对话、点击下钻、模型工具调用和会话证据访问都使用同一权限口径。 |
| FR-07 | 无数据、异常与证据边界 | 区分空样本、权限受限、需要澄清、缺少数据字段、执行无法完成和部分结果。已核实的结论可以连同待查项一起展示。 |
| FR-08 | 对照评测 | 先完成规则基线，再用同样的指标、数据、权限和工具比较模型调查效果。保留原始计数和失败样例。 |

| 编号 | 非功能要求 | 验收边界 |
| --- | --- | --- |
| NFR-01 | 有界执行 | 每条消息的调查最多 3 次工具请求，重复查询、超时和预算耗尽都有明确终态。 |
| NFR-02 | 数据与结果可复算 | 数据来源、版本、文件哈希、统计口径版本及每次查询证据可追查。用户展示所需的是统计值与地区，账号凭据和原始客户标识留在服务侧。 |
| NFR-03 | 本地可运行 | 合成数据演示和默认回归可以在无模型密钥时运行。Olist 真实数据导入与真实模型评测分别提供步骤。 |

## 6. 主要交互

1. **查一个数字。** “2018 年 8 月超期率是多少？”系统查询一次并返回 393/6,351 与 6.19%。
2. **确认比较口径。** 在页面选中 2018 年、超期率作为可见默认指标时，用户问“8 月配送变差了吗”，系统按 7 月与 8 月比较。用户问“最近慢了吗”且缺时间或指标时，先追问需要的条件。
3. **定位变化。** 运营明确要求找出变化集中地区。先比较整体，再按州拆分。发现圣保罗州值得深入时，可继续查该州城市。结果中每次查询都有对应证据。
4. **跨月或跨指标追问。** 用户问“那圣保罗呢”时可以沿用已确认月份和指标。用户明确改查平均耗时后，按新指标查并重新标注分母。
5. **点击继续查。** 结果表中点击圣保罗州，沿用被点击证据的月份与指标并查看州内城市。界面在请求时显示分析中，返回后呈现新增轨迹。
6. **缺失证据。** 用户直接问“是哪家快递的问题”，系统提示缺承运商标识与物流轨迹。如果已有地区定位，展示已确认地区并说明后续要补的数据。

## 7. 验收标准

| 编号 | 对应需求 | 可核验结果 |
| --- | --- | --- |
| AC-01 | FR-01、NFR-02 | 同一来源的同一对 CSV 重复导入后返回同一数据版本 ID，订单计数一致。缺必需列、重复主键和关联缺失均有明确结果或错误记录。 |
| AC-02 | FR-02 | 同日送达算准时，跨月签收按下单月份计，零分母与零超期可区分，平均耗时排除签收早于下单的记录，阶段统计按有效时间顺序取样并使用连续分位数。 |
| AC-03 | FR-03 | 缺少必要条件且无法应用默认值时先澄清，本轮执行零次统计。追问继承适用的已确认条件，显式新条件优先。已具备时间和指标的目标月变差问题可默认比较上一月。 |
| AC-04 | FR-02、NFR-01 | 单月查询和只问“是否变差”的两月比较均只需一次统计。两月超期率样例为 3.38% → 6.19%，增加 2.81 个百分点。 |
| AC-05 | FR-04 | Olist 地区调查能提取圣保罗州与圣保罗市证据，并说明按超期单数增量确定优先级。 |
| AC-06 | FR-04 | 在给定的整体变化小、变化分散及用户指定阶段的场景中，分别选择停止、按需查阶段或直接查指定阶段。单月阶段查询一次即可完成。州账号调查在本州范围内决定城市或阶段查询。 |
| AC-07 | FR-07 | 承运商身份缺失时明确说明证据边界。阶段查询区分来源缺交接字段和所查月份无有效样本。已有证据在后续查询失败或比较只得到一期时能继续展示。 |
| AC-08 | FR-06 | 州账号只能读授权州。对话、点击下钻、直接请求和模型工具四条路径均无法越界。会话证据只对当前账号开放。 |
| AC-09 | FR-05 | 从单月查询、展开证据到点击州查看城市可完整操作。界面展示的数字能在工具结果中核对。 |
| AC-10 | NFR-01、FR-07 | 重复查询和预算耗尽时能停止。查询超时、模型不可用或预算耗尽且未取得证据时展示明确状态。已有可用证据时继续展示。 |
| AC-11 | FR-08、NFR-02 | 完成 20 道开发题及 40 道保留验收题，能复跑两版并查看分子分母、开销和失败案例。 |
| AC-12 | NFR-03 | 可用合成数据启动并完成文档列出的演示，无需模型密钥。真实模型效果另按评测流程实际测量。 |
