# 电商履约分析 Agent 开发规范

本文件约定编码、验证和提交方式。需求与验收编号见 [PRD](PRD.md)，统计口径、接口和权限见[技术架构](技术架构.md)，开发顺序见 [Roadmap](Roadmap.md)。

## 编码与模块约定

- **命名与注释。** Python 函数和变量使用 `snake_case`，类型使用 `PascalCase`。名称体现业务含义和单位，例如 `sample_count`、`delivery_days`、`delta_pp`。注释解释代码里难看出的业务约束，例如跨月签收按下单月份统计的原因。[PEP 8](https://peps.python.org/pep-0008/) · [Google 代码评审指南](https://google.github.io/eng-practices/review/reviewer/looking-for.html)
- **模块职责。** `app/tools/delivery.py` 放两个履约工具各自的名称、描述、入参模型和执行入口。工具适配调用 `queries.py` 的参数化查询，并传入服务端确定的授权范围。`analysis.py` 负责注册工具、安排调查步骤和管理预算。规则调查、模型调查和手动下钻复用查询函数。按改动范围、依赖和权限判断何时拆出独立模块。[软件设计课程讲义](https://web.stanford.edu/~ouster/cgi-bin/cs190-spring15/lecture.php?topic=complexity) · [查询工具规格](技术架构.md#4-两个查询工具fr-02fr-04)
- **接口与类型。** 为跨模块调用的查询函数、API 和模型工具声明入参与返回类型。外部输入在接收边界做运行时校验。类型和接口应保留单位、缺值和有效样本信息，例如超期率 `0` 表示有效样本中零超期，`null` 表示分母为零。
- **状态与日志。** 在能够处理异常的层按[分析接口](技术架构.md#post-apianalysis)规定转换状态。排查记录通过 `analysis_id`、工具名和错误类型关联失败步骤。
- **变更与迁移。** 让每次改动围绕一个可独立验证的目标，相关用例随实现提交。范围较大的重命名、搬迁或格式调整单独提交。重构保持可观察行为，并用回归验证。已在共享环境应用的版本化迁移，由后续迁移向前修正。[《重构》](https://martinfowler.com/books/refactoring.html) · [Google 小变更指南](https://google.github.io/eng-practices/review/developer/small-cls.html) · [版本化迁移实践](https://documentation.red-gate.com/flyway/flyway-concepts/migrations/versioned-migrations)

## TDD 开发流程

1. **先写测试用例，验证红灯。** 选一个验收编号，准备输入、身份和数据，断言期望的工具调用与可观察结果。编写或修改实现前运行这个测试，确认它因目标行为缺失或有缺陷而失败。
2. **用最小实现让测试通过。** 从入口走到真实职责边界。涉及 SQL 口径、月份分组、权限和行级隔离的用例走 PostgreSQL。涉及模型选择的用例可以使用固定输出，但查询和证据构建走真实逻辑。运行新增测试，确认通过。
3. **运行相邻回归，重构后再验证。** 检查正常数据、缺字段、无样本和失败结果。公共口径沉淀到一套查询函数，供规则版、模型版和手动下钻复用。整理完成后重跑新增测试和受影响的回归。
4. **记录验证方式。** 提交说明列出需求或验收编号、运行命令与结果。发现口径、接口或用户可见行为需要调整时，更新相应规格和用例。

第一次写每条路径时优先断言数字、状态、请求次数和证据归属。页面措辞和模型自由表述可能变化，用例以结构化结果与用户可观察行为为准。

### 按层验证

| 测试层 | 首选方式 | 应断言什么 |
| --- | --- | --- |
| Python 单元 | pytest + 手算用例 | 月份解析与继承、明确输入优先、范围判断、参数约束、轮次上限、重复调用指纹 |
| PostgreSQL 集成 | 每次运行使用隔离测试库与真实迁移 | 口径与参考 SQL 一致、两期分组并集、幂等导入、导入失败后的可见版本、总部和州角色的查询范围 |
| API 与编排 | FastAPI 测试客户端 + 固定模型工具序列 + PostgreSQL | 响应状态、轨迹顺序、模型参数校验、权限校验、停止、证据回填和 `partial` 返回 |
| Vue 交互 | 在合成数据模式跑浏览器流程 | 用户能提问、展开查询证据、点击州下钻、看到加载与异常状态，切换账号后不会出现旧会话的迟到结果 |
| 真实模型对照 | 单独运行，使用冻结题集和记录过的模型配置 | 有证据地完成任务、正确选取后续查询、守住权限与证据边界，测量开销 |

每类 PostgreSQL 测试按固定数据复现。单元、数据库集成和默认演示无需模型密钥。Olist 原始 CSV 与真实模型各自有显式命令和运行前提。依赖缺失要在结果里显示对应检查状态，验收记录应以实际运行结果为准。

- [ ] 变更能对应至少一个需求或验收编号。
- [ ] 主路径和相关异常用例都已运行，数值可由手算样本或独立参考 SQL 得到。

## 验收参考

### 验收用例矩阵

| 验收编号 | 最小回归覆盖 | 应看到的结果 |
| --- | --- | --- |
| AC-01 | 同一对 CSV 重导及并发重试、缺必需列、重复订单 ID、重复客户键、缺客户匹配 | 同一对输入返回同一版本 ID，订单数一致。缺必需列或重复键导致导入失败，旧版本仍可查。无法关联的订单计入未知地区。 |
| AC-02 | 同日送达、跨月签收、签收早于下单、缺日期、零分母、两期地区并集、交接时间乱序、两条阶段样本的分位数 | 无样本的比率和耗时为 `null`，有样本零超期为 0。平均耗时排除签收早于下单的记录。阶段样本排除乱序记录，P50 和 P90 按连续分位数计算。 |
| AC-03 | 缺年份、缺且无法推断比较区间、目标月变差默认比较上月、继承和显式覆盖 | 缺项无法补齐时先澄清且执行零次统计。可推断上月时直接比较并展示有效月份。追问沿用适用条件，显式新条件优先。 |
| AC-04 | 问一个数字、只问两月是否变差 | 每条请求统计工具恰好调用一次。Olist 回归核对 208/6,156、393/6,351 和 2.81 个百分点。 |
| AC-05 | 总部调查时变差集中在一个州，继续按城市查 | 证据顺序为整体、州、指定州城市。圣保罗市从 51 单增至 124 单，使用超期单数增量排序时可查到 73 单。 |
| AC-06 | 整体变化小、多个州普遍变差、直接查单月阶段、州账号查本州异常 | 分别覆盖提前停止、根据证据查阶段、一次查单月阶段、州账号整体后直查城市或阶段。固定脚本输出验证调度，真实模型题验证选择质量。 |
| AC-07 | 追问承运商、阶段查询超时、来源缺交接列、字段存在但无有效样本、两期只有一期可算 | 直接查缺字段且无其他证据时返回 `unsupported`，查询成功但所需周期均无有效样本时返回 `no_data`。已有部分证据时返回 `partial` 并保留可用结果。 |
| AC-08 | 总部取全国、州账号请求全国、越权下钻、越权工具调用、直接查询数据库与跨账号读证据 | 州账号所有入口只有授权范围，显式越权得到相应业务状态或不可访问响应。 |
| AC-09 | 选州下钻、从旧证据下钻、切账号、查询无样本、展开轨迹 | 点击沿用被点击证据的月份与指标。数字和工具结果一致，旧响应不会覆盖新会话。 |
| AC-10 | 重复查询、非法参数、耗尽三次工具预算、工具或模型故障、无可用证据 | 最多受理 3 次工具请求，预算内拒绝的请求也计数。最后一次查询补足证据可正常回答。未查全且已有证据返回 `partial`。三次请求全部被拒且没有证据时返回 `unavailable`。 |
| AC-11 | 对照输入一致且能重复运行 | 两套方案使用相同题集、数据、权限和工具预算。报告有样本分母、成本和失败标签。 |
| AC-12 | 合成数据无密钥启动、固定模式走完整演示 | 预设提问可跑通，页面明确显示合成数据和运行模式。 |

### 推荐的第一份手算数据

表里默认日期使用 2018 年，事件时间均为当天 09:00。用它验证样本，正式 Olist 复算放到独立集成用例。

| 订单 | 州 | 状态 | 下单日 | 预计日 | 交接日 | 签收日 |
| --- | --- | --- | --- | --- | --- | --- |
| A | SP | delivered | 07-31 | 08-03 | 08-01 | 08-03 |
| B | SP | delivered | 08-01 | 08-04 | 08-02 | 08-06 |
| C | RJ | delivered | 08-01 | 08-03 | 08-04 | 08-03 |
| D | SP | canceled | 08-01 | 08-05 | 空 | 空 |
| E | SP | delivered | 08-01 | 空 | 08-01 | 08-02 |

预期结果如下。

- 7 月超期率是 0/1。订单 A 在预计日签收，并且归入 7 月。
- 8 月已送达订单数为 3，超期率为 1/2。订单 E 计入已送达单数，缺预计日期所以不进入超期率样本。
- 8 月平均送达耗时为 8/3 天，来自 B、C、E。阶段耗时只有 B 合格，交接前 1 天，交接后 4 天。C 的签收早于交接，E 缺预计送达日期。
- SP 州账号查 8 月已送达订单数为 2，超期率为 1/1。该用例的分母只有 1，结果同时展示样本量。
- 9 月无订单时已送达单数是 0，超期率是 `null`。按州比较 7 月与 8 月时仍会显示 RJ 的 8 月结果，7 月该州为零样本。

另用独立夹具覆盖两个边界，保留上表的基准结果。

- 已送达订单下单于 8 月 2 日、签收于 8 月 1 日。单独查询该样本的平均送达耗时，返回 `null`、有效样本数 0。
- 使用两笔符合阶段样本条件的订单，交接前耗时分别为 1 天、3 天，交接后分别为 2 天、6 天。交接前 P50/P90 为 2/2.8 天，交接后为 4/5.6 天，两段有效样本数均为 2。

Olist 集成用例另核对 [技术架构](技术架构.md) 中的阶段样本数、中位耗时和集中度。它们与 PRD 的超期率构成独立验收项。

### 对照评测规则

#### 题集与运行

开发集 20 题供调试，验收集 40 题留出。40 题包含 10 道单指标、10 道对比、12 道异常调查、8 道澄清及边界。每个用例记录数据版本、角色、原问题、期望状态、标准结果或证据、可接受的后续查询与应停止的条件。

专门评估编排时，为规则版和模型版提供相同的已解析条件，隔离中文理解的影响。完整流程另跑从原问题到 UI 答复的验收。相同口径、相同权限、相同最大工具预算，两套方案各类题的分母一致。评测前冻结题集、集中度及样本阈值、模型和超时配置。

#### 判定与报告

| 指标 | 计算或统计方式 |
| --- | --- |
| 结果正确率 | 数字、单位、授权范围与对应证据都匹配的题数，除以可回答题数。用参考 SQL 生成数值标准。 |
| 调查成功率 | 有足够证据回答用户实际问题的调查题数，除以调查题数。允许多条合理顺序。 |
| 边界通过率 | 正确澄清、阻止越权、区分无数据并指出缺失证据的用例通过数，除以相应题数。 |
| 查询开销 | 总调用与平均调用数、无效或无助查询数、每题 Token、P95 响应时间。分别记录实际统计次数和被拒的工具请求数。 |

任何指标都保留分子、分母及失败样例。对外引用的延迟和结果来自实际评测。合成重放用于验证执行与异常，真实模型运行用于评估模型选择。报告保留模型策略收益有限的场景和相应成本。
