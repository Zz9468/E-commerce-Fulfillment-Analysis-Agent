# 电商履约分析 Agent Roadmap

按熟悉 Python、FastAPI、Vue 3 和 SQL，做出本地可演示的首版估算约 **10 个工作日**。按顺序执行每阶段的步骤，以可核验结果验收。需求编号见 [PRD](PRD.md)，接口和数据口径见[技术架构](技术架构.md)，回归方法见 [开发规范](开发规范.md)。

## M1　把订单数据算对

**时间**　第 1–2 个工作日  
**范围**　FR-01、FR-02、NFR-02 的数据部分，AC-01、AC-02

| 步骤 | 实施内容 | 核验结果 |
| --- | --- | --- |
| 1. 初始化工程 | 初始化 Git，建立后端包、依赖与锁文件、Ruff 和 pytest 配置，准备本地 PostgreSQL、示例环境配置和独立测试库。使用 Compose 时先启动数据库服务。 | 新环境能安装后端依赖、运行检查、连接独立 PostgreSQL 测试库。把实跑命令写入 README。 |
| 2. 迁移与基准 | 建立数据版本和订单事实表的首个迁移。在测试库装载五条合成订单。在 `eval/reference_sql/` 按规格编写独立参考 SQL。 | 空库能应用迁移，测试夹具可重新装载。手算值与参考 SQL 一致。 |
| 3. 实现并验证指标 | 按 AC-02 先写测试并验证红灯，逐步实现已送达计数、超期率、平均耗时、阶段统计。 | PostgreSQL 集成测试通过，覆盖跨月、同日、缺样本、乱序、阶段分位数与地区并集。 |
| 4. 实现订单与客户导入 | 按 AC-01 实现两表校验、连接、双文件版本标识和事务发布。测试缺交接列的导入行为。 | 重导与并发重试返回同一版本 ID，失败导入保留旧版本。缺交接列的输入可载入并保留能力标记。 |
| 5. 用 Olist 复算 | 记录两份原始 CSV 的哈希，导入后用独立参考 SQL 核对全部地区、SP 州、圣保罗市的超期数值，以及阶段样本数、耗时与地区集中度。 | PRD 与技术架构中的参考值可以从已导入版本重现，并记录实跑结果。 |

**进入 M2 的条件**　步骤 1–4 的合成数据回归通过。超期率查询返回比率、分子和有效样本数。阶段查询返回每阶段的 P50、P90、有效样本数及剔除数。Olist 下载受阻时，单独记录步骤 5 的待验证状态，M2 可继续使用合成数据。M1 的完整验收包含步骤 5。

## M2　打通问答页与两套调查流程

**时间**　第 3–5 个工作日  
**范围**　FR-02 至 FR-05，FR-06、NFR-01 的应用层边界，AC-03 至 AC-06、AC-09，以及 AC-08、AC-10 的应用层用例

| 步骤 | 实施内容 | 核验结果 |
| --- | --- | --- |
| 1. 先建立服务端边界 | 用固定演示身份或测试身份建立服务端授权上下文、会话与证据归属。建立规则版和模型版共用的工具执行入口、参数校验和每轮三次受理预算。 | 用例能确认州范围由服务端确定，跨账号证据不可读取，预算内拒绝的请求计数，第四次工具请求不执行。 |
| 2. 实现 API 与会话条件 | 接通 `POST /api/analysis` 的提问和下钻。按明确条件、有效会话条件、页面默认值的顺序处理，再判断是否澄清。 | 单月查数、两月比较、直接查阶段、旧证据下钻和缺项澄清有结构化结果。明确查数只执行一次统计，无法补齐的澄清执行零次。 |
| 3. 上线规则调查路径 | 用合成场景确定整体变化和小样本阈值的开发初值，覆盖提前结束、总部州/城市下钻、阶段查询和州账号本州调查。 | 每条路径可用固定场景复跑，输出完整查询顺序和实际证据，州账号可从本州汇总直接下钻。 |
| 4. 接入模型调查 | 先用固定模型输出重放工具序列，再在模型可用时做工具协议冒烟。复用规则版的查询函数、权限、预算和证据结构。 | 固定输出路径可稳定验证工具参数、调用次序、预算和证据回填。真实模型冒烟的结果单独记录。 |
| 5. 接通 Vue 工作台 | 先用合成数据完成 UI 线框，再接入提问、澄清、两期比较、证据展开和州内城市下钻。页面显示数据版本信息、运行模式和实际查询范围。 | 浏览器能从查数走到证据和下钻。切账号或切会话时，旧请求结果不会覆盖当前视图。 |

**退出条件**　合成数据下能演示查数、比较、按证据追查、提前停止和授权范围限制。应用层归属和预算用例通过。模型协议冒烟若缺可用模型可留待 M4，规则版和固定输出回归可继续验收。

## M3　补齐数据库权限和失败恢复

**时间**　第 6–7 个工作日  
**范围**　FR-06、FR-07、NFR-01、NFR-03，完成 AC-07、AC-08、AC-10、AC-12 的端到端验证

| 步骤 | 实施内容 | 核验结果 |
| --- | --- | --- |
| 1. 补齐双层权限 | 落地总部和 SP 州演示账号、固定角色映射及 PostgreSQL 只读查询角色和行级策略。验证服务端归属与数据库范围一致。 | 总部可查全部地区。州账号通过对话、下钻、直接 API、工具和只读数据库连接均只能取得授权范围的数据。 |
| 2. 收束故障与异常 | 为 SQL、模型、HTTP 配置超时，覆盖重复请求、非法参数、预算用尽、缺字段与空样本。将执行结果按状态表返回。 | 已有部分证据可继续展示。三次工具请求均被拒且无证据时有明确状态。查询成功的空样本与依赖失败可区分。 |
| 3. 整理本地整栈启动 | 补齐整栈 Compose、示例配置、合成数据启动路径、两种演示身份和 README。 | 从干净环境按 README 启动合成模式，无需模型密钥。 |
| 4. 跑浏览器与权限回归 | 走一遍正常调查、权限拒绝、缺证据、注入依赖故障和切账号场景。 | 页面状态与服务端一致，已有证据在后续失败时仍可查看，验收命令和结果可复现。 |

**退出条件**　双层权限、失败收束与无密钥演示通过独立验证。

## M4　跑对照和整理交付

**时间**　第 8–10 个工作日  
**范围**　FR-08、NFR-02、NFR-03，完成 AC-11，复核 AC-01 至 AC-10 及 AC-12

| 步骤 | 实施内容 | 核验结果 |
| --- | --- | --- |
| 1. 补齐真实数据与模型验证 | 完成尚未执行的 Olist 复算和模型工具协议冒烟。 | Olist 数据版本和数值核对结果可追查。模型工具参数与结果回传通过冒烟。 |
| 2. 准备评测并冻结输入 | 准备 20 道开发题与 40 道留出题。用开发集校准阈值，冻结题集、数据版本、口径、阈值、模型、超时与评分规则。 | 两版运行配置可追查，题集含角色、标准答案或证据和可接受路径。 |
| 3. 运行两版对照 | 在相同数据、条件、角色权限和预算下运行，另做原问题到 UI 的验收。 | 报告包含正确率、调查成功率、边界通过率、查询与模型开销的原始计数和失败样例。 |
| 4. 核对交付并留档 | 整理启动、导入、测试与评测说明，录制短演示。按验收编号记录实跑结果。 | 交付物能复跑。外部条件受阻的验收项明确标记，具备完整证据后再关闭。 |

**退出条件**　首版功能验收、真实数据复算、真实模型对照、报告与演示均有实跑证据。

## 依赖与工期调整

| 情况 | 执行方式 |
| --- | --- |
| 本地 Docker 引擎不可用 | 恢复 Docker 引擎或使用可连接的 PostgreSQL 实例，另建隔离测试库。先完成依赖和测试配置，再验证真实迁移与 SQL。 |
| Olist 下载或网络受阻 | 使用合成数据推进实现，记录 Olist 复算待验证，数据可用后补跑。 |
| 目标模型不可用或工具协议不兼容 | 使用规则版和固定模型输出推进应用开发，调整真实模型接入，真实模型评测单独记录并补跑。 |
| 前端工期收紧 | 优先交付提问、两期数字、可展开证据和城市下钻，地区下钻使用表格行操作。 |
| 模型版收益有限 | 报告优势出现在哪类题、失败模式及额外成本，保留规则基线用于演示和对照。 |

依赖版本与实跑命令在 M1 确认。阈值开发初值、模型兼容性和页面线框在 M2 验证。超时配置在 M3 通过故障回归确认。M4 在正式运行前冻结用于对照的全部条件。
