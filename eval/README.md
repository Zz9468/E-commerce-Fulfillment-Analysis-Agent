## 题集与评分

开发集包含 4 道单指标、4 道对比、8 道调查和 4 道边界题。留出集包含 10 道单指标、10 道对比、12 道调查和 8 道边界题。每道题指定题号、数据、账号、原问题、预期状态和可接受的证据顺序。需要进一步验证的结论使用关键数字、单位或业务提示作为答复检查项。数值标准从独立参考 SQL 生成。

- 每道题使用独立会话，并按账号连接真实的 PostgreSQL 只读登录。两版收到同一份冻结的已解析条件。澄清、越权和直接追问承运商的题没有有效查询条件，走公共提问入口，要求零次统计。
- 对每条返回证据，核对数据版本、统计口径、范围、月份、分组、指标、有效样本、数值和证据归属。分组结果按地区逐行对照。数值舍入使用绝对和相对误差均为 `1e-10` 的容差。关键答复检查使用页面可见的单位和舍入规则。
- 调查通过要求得到一条允许的证据顺序，同时满足该题的状态和答复检查。需要停止的题只允许一次整体查询。其余调查可包含额外查询，开销单列。单指标、对比和边界题使用题目规定的查询次数。
- 结果正确率以预期 `answered` 的题为分母。调查成功率使用全部调查题，边界通过率使用全部边界题。每种模式保留逐题失败标签、执行路径、证据摘要、SQL 次数、工具拒绝次数和模型用量。

## 校准与冻结

仅用开发集选择阈值。对升幅 **1、2、3 个百分点**、每期样本 **1、5、20 单**和集中度 **50%、60%、85%** 进行 27 组网格试验。先比较调查通过数，再比较 SQL 次数。同分时沿用开发初值。选中的 **2 个百分点、5 单、60%** 在 8 道开发调查题上全部通过，共 16 次统计。全套开发题通过 20/20。

留出集在评分实现、独立参考 SQL 与题集写入 SHA-256 后运行。数据版本以来源和两个原始 CSV 的字节哈希识别，导入不同数据库时分配的 UUID 会写入运行记录。模型为百炼北京 `qwen3.8-flash`，`reasoning_effort=low`，每次请求 45 秒超时。SQL 连接与语句超时各 5 秒，每轮最多受理 3 次工具请求。

## 原问浏览器验收

用本地开发方式连接已导入 Olist 的数据库，启动指定调查模式的后端。启动前把 `DEFAULT_DATASET_SOURCE` 设为 `olist`。后端使用 README 的默认地址时，Playwright 可按需启动 Vite。

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
$env:M4_WORKSPACE_MODE = 'rule'
npm --prefix frontend run test:e2e -- m4.spec.ts
```

真实模型工作台启动后，把 `M4_WORKSPACE_MODE` 设为 `model`，重跑同一条浏览器用例。录制时先在 `frontend/` 运行 `npx playwright install ffmpeg`，然后设 `M4_DEMO_VIDEO=1`，用例通过后保存到 `eval/demo/workspace.webm`。
